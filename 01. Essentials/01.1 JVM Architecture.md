## 🧠 JVM là gì?

**JVM (Java Virtual Machine)** là một máy ảo — một chương trình mô phỏng một "máy tính trừu tượng" để thực thi **Java Bytecode** (file `.class`). JVM là lý do Java có thể chạy trên bất kỳ nền tảng nào mà không cần biên dịch lại.

## 📦 1. Class Loader Subsystem

Chịu trách nhiệm **nạp class** vào JVM theo 3 bước:

| Bước | Tên | Mô tả |
|------|-----|-------|
| 1 | **Loading** | Đọc file `.class`, tạo object `Class` |
| 2 | **Linking** | Verify bytecode, cấp phát memory cho static fields |
| 3 | **Initialization** | Chạy static initializers và gán giá trị static |

**3 loại ClassLoader:**
```
Bootstrap ClassLoader  →  Load rt.jar (java.lang.*, java.util.*)
    ↑ parent
Extension ClassLoader  →  Load lib/ext/*.jar
    ↑ parent
Application ClassLoader →  Load classpath của ứng dụng
```

> 💡 **Delegation Model:** ClassLoader con luôn hỏi cha trước khi tự load — tránh class bị load 2 lần.

## 💾 2. Runtime Data Areas (Memory)

### Heap — Vùng nhớ dùng chung
```
Heap
├── Young Generation
│   ├── Eden Space       ← new objects born here
│   ├── Survivor S0
│   └── Survivor S1
└── Old Generation (Tenured)  ← long-lived objects
```
- **Tất cả Objects và Arrays** được tạo trong Heap
- Được quản lý bởi [[01.3 Garbage Collection]]
- Chia sẻ giữa tất cả threads

### Stack — Vùng nhớ per-thread
```java
public int add(int a, int b) {  // ← Stack frame được tạo
    int result = a + b;          // ← local variables trong frame
    return result;               // ← frame bị pop khi method return
}
```
- Mỗi **thread** có 1 stack riêng
- Mỗi **method call** tạo 1 **Stack Frame** mới chứa: local variables, operand stack, reference đến Constant Pool
- `StackOverflowError` xảy ra khi stack đầy (đệ quy vô tận)

### Method Area (Metaspace từ Java 8+)
- Lưu trữ **class metadata**: tên class, method, field, bytecode
- Lưu **static variables** và **constants**
- Trước Java 8: gọi là **PermGen** (dễ gây `OutOfMemoryError: PermGen space`)
- Từ Java 8: **Metaspace** — dùng native memory, không giới hạn cứng

### PC Register (Program Counter)
- Mỗi thread có 1 PC Register
- Lưu địa chỉ instruction JVM đang thực thi

## ⚡ 3. Execution Engine

### Interpreter
- Đọc và thực thi bytecode từng lệnh một
- **Chậm** vì phải interpret mỗi lần gặp

### JIT Compiler (Just-In-Time)
- Monitor code execution, phát hiện **"hot methods"** (chạy nhiều lần)
- Compile bytecode → **native machine code** để chạy trực tiếp
- Kết quả được cache → lần sau gọi lại dùng native code → **Nhanh hơn nhiều**

```
Bytecode → [Interpreter] → thực thi từng bước
               ↓ (sau N lần gọi)
           [JIT Compiler] → Native Code → thực thi trực tiếp (nhanh ~10-100x)
```

> 💡 Đây là lý do Java **"warm up"** chậm nhưng sau đó chạy **rất nhanh**.

## 🔁 Luồng Xử Lý Từ Source → Execution

```
HelloWorld.java
      ↓  javac (compiler)
HelloWorld.class  (bytecode)
      ↓  ClassLoader
  Method Area
      ↓  Execution Engine
  Thực thi trên CPU (native)
```

## ⚖️ So Sánh: Java/JVM vs Ruby / Ruby on Rails

### 1. Mô Hình Thực Thi (Runtime Model)

| Tiêu chí | Java (JVM) | Ruby (MRI/CRuby) | JRuby |
|---|---|---|---|
| **Runtime** | JVM — máy ảo riêng | Interpreter viết bằng C | Ruby chạy trên JVM |
| **Biên dịch** | `.java` → bytecode (`.class`) → JIT native | Parse trực tiếp → AST → thực thi | Bytecode JVM |
| **Warm-up** | Chậm lúc đầu, nhanh dần (JIT) | Nhanh khởi động, không có JIT mặc định | Tương tự JVM Java |
| **Native Image** | GraalVM Native Image (khởi động <10ms) | Không có tương đương | Không áp dụng |

```
Java:    .java → javac → .class (bytecode) → JVM → JIT → Native Code
Ruby:    .rb   → MRI Interpreter → YARV bytecode → thực thi (không JIT mặc định)
JRuby:   .rb   → JRuby → JVM bytecode → JIT → Native Code
```

> 💡 **JRuby** là bằng chứng rằng JVM đủ mạnh để chạy cả ngôn ngữ khác — Ruby code cũng được hưởng lợi từ JIT của JVM khi dùng JRuby.

---

### 2. Quản Lý Bộ Nhớ

| Tiêu chí | Java (JVM) | Ruby (MRI) |
|---|---|---|
| **Heap** | Phân vùng rõ ràng: Young / Old Generation | Heap đơn giản hơn, không phân vùng generation rõ ràng |
| **GC Algorithm** | G1GC, ZGC, Shenandoah (low-pause) | Mark-and-Sweep + Incremental GC (Ruby 2.x+) |
| **GC Tuning** | Rất nhiều tùy chọn (`-Xmx`, `-XX:+UseZGC`…) | Ít tùy chọn hơn, ít kiểm soát hơn |
| **Memory footprint** | Cao hơn (JVM overhead ~50–200MB) | Thấp hơn cho ứng dụng nhỏ |
| **Object model** | Mọi object đều là reference trên Heap (trừ primitives) | Mọi thứ đều là object (kể cả `nil`, `true`, `false`) |

---

### 3. Concurrency (Xử Lý Đồng Thời)

| Tiêu chí | Java | Ruby (MRI) | Ruby (JRuby) |
|---|---|---|---|
| **Thread model** | True OS threads — chạy song song thật sự | GIL (Global VM Lock) — chỉ 1 thread chạy tại một thời điểm | True threads (no GIL) |
| **Parallelism** | ✅ CPU-bound tasks được hưởng lợi | ❌ GIL ngăn chặn parallelism cho CPU-bound | ✅ Như Java |
| **Concurrency** | Executors, ForkJoinPool, Virtual Threads (Java 21+) | Threads + Fiber (lightweight coroutine) | Tương tự JVM |
| **Async** | CompletableFuture, Project Reactor | EventMachine, Async gem | — |

> ⚠️ **GIL của Ruby MRI** là điểm yếu lớn nhất so với Java: dù tạo nhiều threads, CPU-bound code vẫn chạy tuần tự. I/O-bound tasks ít bị ảnh hưởng hơn.

---

### 4. Type System

| Tiêu chí | Java | Ruby |
|---|---|---|
| **Typing** | **Static** — kiểm tra tại compile time | **Dynamic** — kiểm tra tại runtime |
| **Type inference** | `var` từ Java 10+ | Không cần khai báo type |
| **Generics** | ✅ (`List<String>`) | ❌ Không có generics |
| **Null safety** | Dễ bị `NullPointerException` | `nil` — tương tự, có `NoMethodError` |
| **Optional typing** | Không (dùng `Optional<T>` wrapper) | Sorbet / RBS cho static type checking (tùy chọn) |

---

### 5. Framework: Spring Boot vs Ruby on Rails

| Tiêu chí | Spring Boot (Java) | Ruby on Rails |
|---|---|---|
| **Triết lý** | Convention + Configuration | **Convention over Configuration** (cực đoan hơn) |
| **Scaffolding** | Ít, cần cấu hình nhiều hơn | `rails generate` tạo toàn bộ MVC tự động |
| **ORM** | JPA/Hibernate (annotation-based) | ActiveRecord (DSL tự nhiên hơn) |
| **Routing** | `@GetMapping`, `@PostMapping`… | `config/routes.rb` — DSL ngắn gọn |
| **Boilerplate** | Nhiều hơn | Ít hơn |
| **Performance** | Cao hơn đáng kể (JIT, multithreading) | Thấp hơn nhưng đủ cho hầu hết web app |
| **Boot time** | ~2–10s (hoặc ms với GraalVM) | ~5–30s (Rails nổi tiếng boot chậm) |
| **Ecosystem** | Maven Central — rất lớn | RubyGems — lớn, nhưng nhỏ hơn Java |
| **Phù hợp** | Enterprise, microservices, high-throughput | Startup, MVP, CRUD app nhanh |

```
Ví dụ CRUD — Rails (ActiveRecord):
  rails generate scaffold Post title:string body:text
  → tự tạo Model + Controller + Views + Migration + Routes

Ví dụ CRUD — Spring Boot:
  → Tự viết Entity, Repository, Service, Controller, DTO
  → Chi tiết hơn nhưng kiểm soát nhiều hơn
```

### 6. Tổng Kết

| | Java / Spring Boot | Ruby / Rails |
|---|---|---|
| **Điểm mạnh** | Performance, type safety, concurrency, enterprise | Developer productivity, DX tốt, rapid prototyping |
| **Điểm yếu** | Verbose, boilerplate nhiều, boot time | GIL, hiệu năng thấp hơn, magic ẩn |
| **Khi nào dùng** | High-traffic, microservices, long-running service | MVP, startup, team nhỏ, deadline nhanh |
| **Chạy trên JVM?** | Nguyên bản | Chỉ khi dùng JRuby |
