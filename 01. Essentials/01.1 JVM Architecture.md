## 🧠 JVM là gì?

**JVM (Java Virtual Machine)** là một máy ảo — một chương trình mô phỏng một "máy tính trừu tượng" để thực thi **Java Bytecode** (file `.class`). JVM là lý do Java có thể chạy trên bất kỳ nền tảng nào mà không cần biên dịch lại.

## 📦 1. Class Loader Subsystem

Chịu trách nhiệm **nạp class** vào JVM theo 3 bước:

| Bước | Tên | Mô tả |
|------|-----|-------|
| 1 | **Loading** | Đọc file `.class`, tạo object `Class` |
| 2 | **Linking** | Verify bytecode, cấp phát memory cho static fields |
| 3 | **Initialization** | Chạy static initializers và gán giá trị static |

**3 loại ClassLoader:**
```
Bootstrap ClassLoader  →  Load rt.jar (java.lang.*, java.util.*)
    ↑ parent
Extension ClassLoader  →  Load lib/ext/*.jar
    ↑ parent
Application ClassLoader →  Load classpath của ứng dụng
```

> 💡 **Delegation Model:** ClassLoader con luôn hỏi cha trước khi tự load — tránh class bị load 2 lần.

## 💾 2. Runtime Data Areas (Memory)

### Heap — Vùng nhớ dùng chung
```
Heap
├── Young Generation
│   ├── Eden Space       ← new objects born here
│   ├── Survivor S0
│   └── Survivor S1
└── Old Generation (Tenured)  ← long-lived objects
```
- **Tất cả Objects và Arrays** được tạo trong Heap
- Được quản lý bởi [[01.3 Garbage Collection]]
- Chia sẻ giữa tất cả threads

### Stack — Vùng nhớ per-thread
```java
public int add(int a, int b) {  // ← Stack frame được tạo
    int result = a + b;          // ← local variables trong frame
    return result;               // ← frame bị pop khi method return
}
```
- Mỗi **thread** có 1 stack riêng
- Mỗi **method call** tạo 1 **Stack Frame** mới chứa: local variables, operand stack, reference đến Constant Pool
- `StackOverflowError` xảy ra khi stack đầy (đệ quy vô tận)

### Method Area (Metaspace từ Java 8+)
- Lưu trữ **class metadata**: tên class, method, field, bytecode
- Lưu **static variables** và **constants**
- Trước Java 8: gọi là **PermGen** (dễ gây `OutOfMemoryError: PermGen space`)
- Từ Java 8: **Metaspace** — dùng native memory, không giới hạn cứng

### PC Register (Program Counter)
- Mỗi thread có 1 PC Register
- Lưu địa chỉ instruction JVM đang thực thi

---

## ⚡ 3. Execution Engine

### Interpreter
- Đọc và thực thi bytecode từng lệnh một
- **Chậm** vì phải interpret mỗi lần gặp

### JIT Compiler (Just-In-Time)
- Monitor code execution, phát hiện **"hot methods"** (chạy nhiều lần)
- Compile bytecode → **native machine code** để chạy trực tiếp
- Kết quả được cache → lần sau gọi lại dùng native code → **Nhanh hơn nhiều**

```
Bytecode → [Interpreter] → thực thi từng bước
               ↓ (sau N lần gọi)
           [JIT Compiler] → Native Code → thực thi trực tiếp (nhanh ~10-100x)
```

> 💡 Đây là lý do Java **"warm up"** chậm nhưng sau đó chạy **rất nhanh**.

## 🔁 Luồng Xử Lý Từ Source → Execution

```
HelloWorld.java
      ↓  javac (compiler)
HelloWorld.class  (bytecode)
      ↓  ClassLoader
  Method Area
      ↓  Execution Engine
  Thực thi trên CPU (native)
```
